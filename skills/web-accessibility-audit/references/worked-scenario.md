# Worked scenario — web-accessibility-audit

## Appropriate request
Task: diagnose keyboard trap in a checkout modal.

## Near-miss request
Not this task: change card shadows and brand colors.

## Domain-specific approach
Audit a single user journey: entry focus, tab order, modal open/close, focus return, error messages and 200% zoom. Capture each issue with exact action, expected WCAG behavior, observed state and severity. Automated axe findings are supporting evidence only; do not claim screen-reader testing without actually using one.

## Acceptance evidence
WCAG criterion, reproduction and relevant DOM path, test access, fix and retest or BLOCKED.

This is an example, not a completed runtime test. Do not claim real test results without evidence.
